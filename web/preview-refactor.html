用户认证模块技术方案

本文档详细描述了用户认证模块的整体架构设计，包括 JWT token 生命周期管理、Session 策略、OAuth2.0 集成方案以及安全审计日志的实现路径。方案基于已有 PRD 需求文档，结合代码仓库现状进行分析。

vault://projects/auth-module/technical-spec.md
claim 风险已清空 5 条 raw 来源 2 个开放问题 auth security JWT
Claims / 论断
JWT token 应使用 RS256 算法签名，而非 HS256，以避免密钥泄露导致的伪造风险。
已验证 来源: OWASP Token Storage Cheat Sheet
Session TTL 设置为 30 分钟，Refresh Token TTL 设置为 7 天，符合行业最佳实践。
待重审 来源: RFC 6749 Section 5
OAuth2.0 PKCE 流程适用于公开客户端（SPA / Mobile），能有效防止授权码拦截攻击。
已验证 来源: RFC 7636
审计日志应记录所有认证事件（登录、登出、token 刷新、密码变更），保留周期不少于 90 天。
审阅中 来源: SOC2 Type II 合规要求
