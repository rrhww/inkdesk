Lint 只能证明包结构可解析，不能证明 Skill 在真实任务中可靠

历史记录显示，两个 Skill 曾通过 structural 和 safety lint，却在真实任务中产生了错误路由与不完整交付。因此 active 晋级需要同时覆盖“能加载”“不越权”“能完成任务”和“人工确认边界”四类证据。

  1. 结构正确不等于行为正确。 `tech-solution` 的早期版本遗漏了测试范围，但 contract 仍然合法。
  2. 路由描述需要真实反例验证。 `skill-router` 曾把普通语法问题错误路由到宽入口。
  3. 写权限必须单独审查。 行为可用的 Skill 仍可能声明过宽的 Wiki 或代码写入范围。
