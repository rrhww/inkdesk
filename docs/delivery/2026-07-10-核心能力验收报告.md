# Inkdesk 核心能力验收报告

日期：2026-07-10

## 验收结论

**当前版本不通过核心能力正式验收。**

项目已经具备 `Sources -> Wiki -> Schema -> Skills -> Dev Run` 的主体实现，隔离环境下后端业务测试、前端构建和真实浏览器六阶段流程均可工作。但当前 Vault Health Gate 为 `FAILED`，标准测试命令不能稳定全绿，Evaluation 仍只有数据与运行清单骨架，13 个 Skill 全部处于 `draft`。因此可以判定为“核心链路已成形、可继续迭代”，不能判定为“参考思想已经完整落地并可发布”。

## 验收基线

本次基线来自：

- `docs/references/AI研发自动化：Wiki知识库+技能包.md`
- `docs/references/AI研发自动化：Wiki知识库+技能包-项目映射.md`
- `docs/product/最小可行产品需求文档.md`
- `docs/delivery/本地全栈验收.md`

核心能力按以下链路验收：

```text
Sources -> LLM-Wiki -> Schema -> Skills -> Evaluation -> Harness
             |            |
          Ingest/Query/Lint
```

## 关键问题

### P0：Vault Health Gate 失败

当前运行结果：

- Health Score：75
- Gate Status：`FAILED`
- `KB_MISSING_SECTION`：4 条 error
- `KB_OUTDATED_REFERENCE`：4 条 error
- `KB_ORPHAN_PAGE`：4 条 info

在参考思想中，Lint / schema gate 是知识质量的发布门禁。Gate 未通过时，不能宣称 Wiki 已达到可持续维护状态，也不应启动 Evaluation 晋级。

### P0：标准验收命令不具备环境隔离

`Settings` 自动读取 `server/.env`，而 `tests/conftest.py` 没有清空 provider profile、model、base URL 和 API key。结果是测试行为依赖开发者本机配置：

- DeepSeek 默认模型断言被本机 `INKDESK_AGENT_MODEL` 覆盖。
- OpenAI 结构化输出断言被本机 DeepSeek profile 影响。
- 原本离线的 research 测试发生真实网络等待，全套超过 15 分钟未退出。

隔离这些变量后，后端 285 项通过，说明主要业务逻辑健康，但标准命令仍不满足可复现验收要求。

### P0：Evaluation 闭环尚未成立

当前 `/api/evals/golden` 返回 0 个任务。`EvaluationService` 只能保存/读取 golden、rubric 和创建状态为 `created` 的 manifest，没有看到真实任务执行、LLM Judge、评分汇总、版本对比或 promotion gate。参考文档要求的 evaluation-driven 改进尚不可验收。

### P1：Fullstack E2E 门禁失真

发现三类问题：

1. Playwright Web Server 使用 `3301`，FastAPI CORS 只允许 `http://localhost:3000`，导致客户端详情请求在 E2E 环境被拦截。
2. 编译页同时存在同名 `h1/h2`，测试使用宽泛 heading locator，触发 strict mode violation。
3. 测试期望 GET `/api/runs/{id}/events` 返回 404，但该路径只支持 POST，FastAPI 正确返回 405。

在 CORS 允许的 `localhost:3000` 上使用精确 locator 补验，真实 Run 详情、阶段轨道、Ask 入口、六阶段推进和完成态均通过。

### P1：前端单测与已交付功能不同步

Skill Workbench 已有路由、页面和 13 个有效 Skill，但 `app-shell.test.ts` 仍期望不含“技能”的旧导航顺序，导致 `npm test` 失败。这是测试基线陈旧，不是 Skill 入口本身的回归。

### P1：文档与端口配置漂移

- README、本地全栈验收和服务端说明使用后端端口 `8080`。
- `web/.env.local.example` 和当前运行后端使用 `8000`。

新环境按文档启动后，前端默认配置无法连接该后端。

- 打开 Run 详情，任务标题、六阶段轨道和 Ask 入口可见。

- 缺失 Run 返回 404。

## 建议复验顺序

1. 隔离 pytest 的 `.env` / provider 配置，保证标准 `python -m pytest` 在任意开发机可复现。
2. 修正前端导航单测和 fullstack E2E 的端口、CORS、locator、HTTP 方法预期。
3. 处理 8 条 Wiki Health error，使 Gate 变为 `PASSED`。
4. 建立最小 Golden Tasks、rubric、真实评分结果和 promotion gate。
5. 将 13 个 Skill 从 `draft` 晋级到经过评测的可用状态。
6. 统一文档、示例环境变量和实际后端端口。
7. 重新执行文档中的全部标准命令，要求不依赖额外手工环境清理且全部通过。

## 放行判定

本轮判定：**不放行**。

下一次放行至少需要同时满足：

- 标准后端、前端、构建和 fullstack E2E 命令全部通过。
- Wiki Health Gate 为 `PASSED`。
- Golden Tasks 非空，并能产出可审计评分结果。
- Skill 晋级有 Evaluation 证据，不再全部停留在 `draft`。
- 端口与环境文档一致，新环境可以按文档一次启动成功。
