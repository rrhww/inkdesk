# Inkdesk v0.2.0 Release Notes (Draft)

## Highlights

- First Inkdesk-native Harness Runtime with file-backed Runs and resumable SSE.
- Governed Claude Agent Executor with real tool loops, isolated Specialist worktrees, and a tool-free Lead synthesis session.
- Better Harness Agent Work Loop gates and four audited Agency Agents profiles.
- Standard Agent Skills discovery plus opt-in `inkdesk.yaml` executable capabilities.
- `harness-audit-v1`: frozen Git evidence, three parallel reviews, validated Findings, Vault proposal, graph refresh, and Run Inspector.

## Quick Start

```powershell
python -m pip install -e ".\server[dev,claude]"
python -m pip install -e ".\server\inkdesk_skill_sdk"
inkdesk run harness-audit --executor claude --depth quick --repo .
```

For the Docker offline demonstration, use `--executor deterministic`. Real
Claude execution is host-only in this release. Claude Code runs in native safe
mode and can use a CCSwitch-managed third-party Provider without importing user
Skills, Hooks, MCP servers, or CLAUDE.md. Inkdesk PreToolUse hooks remain the
mandatory permission boundary even when user settings contain allow rules.

## Compatibility

The `tech-solution` CLI, API, SSE events, and generated path remain compatible
with v0.1.0. Legacy `contract.json` Skills remain readable with a deprecation
warning. `nextSkills` remains available only to legacy routing; new workflows
own their stage graph in Harness Runtime.

## Known Limits

- Codex is protocol-reserved and returns `EXECUTOR_NOT_AVAILABLE`.
- No code generation, Finding repair, persistent workspace write, push, or PR.
- Approval is limited to one policy-classified read-only command and cannot cross Capability hard denials.
- Claude Code must support `--safe-mode`; Provider credentials and model mapping
  remain managed by Claude Code or CCSwitch and are never copied into Inkdesk.
- In-progress Agent sessions are marked `interrupted` after restart and are not resumed.
