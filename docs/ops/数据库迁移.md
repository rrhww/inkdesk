# 数据库迁移

## 唯一入口

在直接启动 Python 后端前执行：

```powershell
cd server
python -m inkdesk_server.db_migrations status
python -m inkdesk_server.db_migrations upgrade
python -m inkdesk_server.db_migrations check
```

`status` 只读输出状态。`upgrade` 是唯一允许写入 revision 的入口；它会对空库执行 Alembic baseline，或只在 PostgreSQL schema 精确匹配 F01 兼容 digest 时 stamp `f02_0001`。不要手工执行 `alembic stamp`。

Docker server entrypoint 会先执行同一条 `upgrade` 命令。迁移失败时容器非零退出，Uvicorn 不会启动。

## 状态和原因码

| 状态或原因码 | 含义 | 安全动作 |
| --- | --- | --- |
| `EMPTY` | 没有应用表和 revision | 执行 `upgrade` |
| `F01_CURRENT_UNMANAGED` | PostgreSQL 结构精确匹配 F01，但未受管 | 执行 `upgrade` 进行严格 stamp |
| `MANAGED_CURRENT` | revision 已到 head 且 schema 无 drift | 可以启动应用 |
| `DB_REVISION_BEHIND` | 空库、未接管或已知旧 revision | 先执行 `upgrade` |
| `DB_REVISION_UNKNOWN` | revision 不在当前 graph | 停止，确认数据库与部署包来源 |
| `DB_SCHEMA_UNSUPPORTED` | partial、未知或不匹配 schema | 停止，制定专门转换方案 |
| `DB_SCHEMA_DRIFT` | revision 到 head 但真实 schema 不一致 | 停止，恢复备份或新增明确 revision |
| `DB_MIGRATION_LOCK_TIMEOUT` | 30 秒内未取得 PostgreSQL advisory lock | 确认是否有 migration 正在执行后重试 |
| `DB_MIGRATION_FAILED` | revision、stamp 或 postflight 失败 | 保留日志，应用不得启动 |

错误输出不会包含数据库密码或完整连接 URL。

## 恢复

F02 baseline 不支持 destructive downgrade。若 schema 或数据指纹异常，使用已认证 F01 evidence 中的 PostgreSQL dump 和 Vault ZIP 恢复到隔离目标验证；不要覆盖源库。正常回退到 F01 应用代码时，可以保留仅新增的 `alembic_version` 表。

真实演练命令：

```powershell
pwsh -File scripts/f02/verify-migrations.ps1 `
  -F01EvidenceDir .local/f01-baseline/20260711T113950Z
```

该命令只操作 `inkdesk_f02_*` 临时数据库，并将证据写入 `.local/f02-migrations/`。
