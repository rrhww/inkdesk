# error-patterns

test-fix 诊断测试失败时可参照的常见错误模式。每个模式包含：特征、根因假设、诊断方法。

## 模式索引

### EP-01: 值偏差
- **特征**：测试断言失败，期望值 ≠ 实际值，且差值固定或有规律
- **根因假设**：
  - 计算结果因逻辑变更偏移（最常见）
  - 测试数据过期（期望值不再正确）
  - 浮点精度问题（小数比较未用 approx）
- **诊断**：检查最后一次变更中影响该计算路径的代码；对比变更前后的中间值

### EP-02: 空值 / None
- **特征**：测试报 `AttributeError`、`TypeError: 'NoneType'` 或断言 None
- **根因假设**：
  - 某个前置步骤未正确初始化
  - 数据库/文件未找到返回 None 而非异常
  - mock 未设置返回值
- **诊断**：从报错行向上追溯——哪个变量为 None？它是怎么来的？

### EP-03: 路径/文件缺失
- **特征**：`FileNotFoundError`、ImportError、路径拼接错误
- **根因假设**：
  - 文件被移动或重命名
  - 工作目录变更
  - 环境变量未设置导致路径解析失败
- **诊断**：检查最近的文件变更记录（git log --diff-filter=R）

### EP-04: 超时
- **特征**：测试长时间运行后失败，或 `TimeoutError`
- **根因假设**：
  - 被调用的外部服务不可达
  - 死锁或无限循环
  - 资源耗尽（连接池满了）
- **诊断**：查看超时前的最后一条日志；检查是否有并发操作未正确清理

### EP-05: 竞态
- **特征**：测试间歇失败，同一输入有时 pass 有时 fail
- **根因假设**：
  - 测试间共享可变状态
  - 异步操作未等待完成
  - 时间依赖（如 `sleep(1)` 在 CI 慢机器上不够）
- **诊断**：多次重复运行（pytest --count=20）；检查共享 fixture scope

### EP-06: 序列化/编码
- **特征**：`UnicodeDecodeError`、JSON parse error、bytes/str 类型错误
- **根因假设**：
  - 编码不一致（如 gbk vs utf-8）
  - 响应格式变更（API 返回了新字段类型）
- **诊断**：检查输入/输出的编码声明；检查最近 API 响应格式变更

## 不做

- 不把所有失败都硬匹配到某个模式——新类型的错误需要深入诊断
- 不在无证据时断言「这就是竞态」
