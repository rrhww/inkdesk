# diagnostic-tree

诊断决策树——当面对异常现象时，沿此树逐层缩小排查范围。

test-fix 和 problem-solve 均可使用此树，但 test-fix 聚焦测试失败，problem-solve 聚焦线上/环境异常。

## test-fix 诊断树

```
测试失败
  │
  ├─ 失败稳定重现？
  │    ├─ YES → 是代码变更引入的 bug
  │    │         │
  │    │         ├─ 最近 commit 引入了这个失败？
  │    │         │    ├─ YES → 检查该 commit 的 diff → 定位引入点
  │    │         │    └─ NO  → 是测试环境/数据变更 → 检查 CI 环境 diff
  │    │         │
  │    │         └─ 是否测试本身有问题？
  │    │              ├─ 期望值过期 → 标记「测试修正」
  │    │              └─ 逻辑漏洞 → 修复实现
  │    │
  │    └─ NO  → 间歇失败
  │              ├─ 时间相关？→ 检查 sleep/wait/超时设置
  │              ├─ 资源竞争？→ 检查共享 fixture / 并发
  │              └─ 外部服务？→ 检查 mock / 连接状态
  │
  └─ 失败只出现在 CI 上？
       ├─ YES → 环境差异（OS/路径/编码/依赖版本）
       └─ NO  → 本地环境问题
```

## problem-solve 诊断树

```
异常现象
  │
  ├─ 信号类型
  │    ├─ 报错/异常 → 从异常堆栈出发
  │    ├─ 性能劣化 → 从监控指标出发
  │    └─ 功能异常 → 从用户报告出发
  │
  ├─ 范围判断
  │    ├─ 代码 bug —— 逻辑错误、边界未处理、异常未捕获
  │    ├─ 配置错误 —— 环境变量、连接字符串、开关状态
  │    ├─ 环境问题 —— 依赖缺失、版本不兼容、资源不足
  │    ├─ 依赖变更 —— 上游 API 变更、库升级行为变化
  │    └─ 数据异常 —— 脏数据、schema 不匹配、迁移遗漏
  │
  └─ 近期变更关联
       ├─ 最近 24h 内有代码变更？→ 检查 diff
       ├─ 最近有依赖升级？→ 检查 changelog
       └─ 最近有配置修改？→ 检查 config diff
```

## 终止条件

- 根因唯一确定，有完整证据链
- 所有可验证路径均已排除，剩余可能需要环境外信息

## 不做

- 不在第一步就跳到结论
- 不跳过证据收集步骤
