# search-strategy

从 wiki 中检索相关信息的多路策略。answer-from-wiki 执行检索时优先参照本规则。

## 检索路径

按以下路径并行搜索，不依赖单一索引：

| 路径 | 内容 | 匹配方式 |
|------|------|---------|
| `wiki/entities/` | 文件/函数/模块实体 | 关键词 + 模糊匹配 |
| `wiki/concepts/` | 概念、术语、设计决策 | 语义匹配 + 标题匹配 |
| `wiki/topics/` | 主题页面、流程说明 | 全文搜索 |
| raw 材料 | 未处理的摄入内容 | 关键词匹配 |

## 相关性排序

1. **直接命中**：页面标题或 frontmatter 中的 tags/keywords 精确匹配问题关键词
2. **概念关联**：页面内容中包含问题中实体的引用（如问题提 `auth.py` → 页面的 wikilink 指向 auth）
3. **上下文相关**：页面所属 topic 与问题领域相同
4. **弱相关**：仅包含问题中的通用词

## 查询扩展

- 中文问题：同时搜索中文和对应的英文术语（如「认证」→ 也搜索 `auth`, `authentication`）
- 缩写：展开常见缩写（如 `KB` → `knowledge base`）
- 分割：长问题拆分为多个子查询，分别搜索

## 停止条件

- 已找到 ≥3 个高相关页面（直接命中）
- 已搜索所有 4 条路径
- 检索结果 >20 条时截断并标记「可能存在更多」

## 不做

- 不编造检索结果中不存在的信息
- 不在单路径无结果时宣布「wiki 中没有相关信息」（需所有路径搜索完毕）
