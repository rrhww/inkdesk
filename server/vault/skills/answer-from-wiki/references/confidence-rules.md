# confidence-rules

answer-from-wiki 回答中置信度标注的规则。

## 三级置信度

| 级别 | 定义 | 判定条件 |
|------|------|---------|
| **高** | 来源可直接回答 | wiki 页面中的某个段落直接覆盖了问题的核心事实，不需要推断 |
| **中** | 来源间接支持 | 需要组合 2 个以上页面的信息做推断，或来源内容部分覆盖问题 |
| **低** | 来源不足 | 只有模糊相关内容，或需要不被 wiki 记录的外部知识 |

## 标注格式

每条关键声明后紧跟置信度标签：

```
[高 | 来源: wiki/concepts/auth-flow.md §3]
[中 | 来源: wiki/entities/user.py + wiki/concepts/session.md]
[低 | 推断自 wiki/topics/deployment.md]
```

## 何时标记知识缺口

以下情况必须标记缺口：
- 问题有明确答案域但 wiki 中完全没有相关内容
- wiki 中有部分内容但关键环节缺失（如「流程的步骤 3 未记录」）
- wiki 中存在矛盾信息未解决

缺口格式：
```
[知识缺口] 问题涉及「xxx」，但 wiki 中缺少关于「yyy」的记录。
建议：通过 ingest-source 补充相关材料。
```

## 不做

- 不在低置信度时仍用高置信度标签
- 不把 LLM 自身知识当作 wiki 来源
