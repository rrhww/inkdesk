# architecture-constraints

coding 在执行时需要遵守的架构硬约束。这些是不可绕过的规则——与 architecture-patterns（启发式建议）不同。

## 硬约束

### C1: 不改变契约
- 方案中定义的接口契约（输入/输出/错误）不能被实现偏离
- 如果发现需要修改契约 → 暂停，返回 tech-solution

### C2: 不引入新外部依赖
- 如需添加新的第三方库 → 必须获得用户确认
- 例外：同一生态内的标准库（如 Python stdlib）

### C3: 数据库 migration 需要确认
- 任何 schema change（表结构变更、索引增删、字段类型变更）→ 必须先获得用户确认
- 禁止在 coding 流程中自动执行 migration

### C4: API breaking change 需要确认
- 修改已有 API 的签名或行为 → 必须先获得用户确认
- 新增 API 不受此约束

### C5: 单模块变更范围
- 每个实现步骤只修改方案指定的模块
- 如果发现需要修改未在方案中列出的模块 → 记录偏差，评估是否需要返回 tech-solution

## 违反后果

- C1/C2/C3/C4 违规 → 停止当前步骤，标记阻塞，等待用户处理
- C5 违规 → 记录偏差继续但不自动扩大范围

## 不做

- 不修改这些约束本身
- 不在紧急情况下跳过约束（无例外机制）
