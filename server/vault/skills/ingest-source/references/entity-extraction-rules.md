# entity-extraction-rules

从 raw 材料中识别实体和关系的规则。本文件是 ingest-source 的领域知识补充——实体识别应优先参照本文规则，而非依赖 LLM 临时判断。

## 内容类型识别

| 类型 | 判定特征 | 提取策略 |
|------|---------|---------|
| Markdown | `*.md` 扩展名，或 `#`/`-`/`[]()` 标记 | 按标题层级分段提取 |
| 纯文本 | 无结构化标记 | 按段落提取，注意列表项 |
| 代码 | `*.py`/`*.ts`/`*.rs` 等，或缩进/关键字密度高 | 提取函数签名、类声明、模块导入 |
| HTML | `<!DOCTYPE>`/`<html>`/标签密度高 | 提取文本内容，忽略样式/脚本 |

## 实体类型与提取启发式

| 类型 | 示例 | 提取规则 |
|------|------|---------|
| 文件 | `auth.py`, `UserService.ts` | 路径 + 文件名，用于代码相关材料 |
| 函数/方法 | `authenticate()`, `handleSubmit` | 名称 + 签名 + 所在文件 |
| 概念 | "幂等初始化", "乐观锁" | 术语 + 定义 + 上下文句 |
| 依赖 | "依赖 PostgreSQL 15", "需要 Redis" | 依赖项 + 版本约束 + 用途 |
| 配置项 | "MAX_CONNECTIONS=100" | 键 + 值 + 位置 |
| 边界条件 | "并发不超过 1000 QPS" | 条件 + 阈值 + 来源 |

## 与现有 wiki 对照

- 新实体：wiki 中无匹配 → 标注 `new`
- 已有实体：wiki 中有相同标识 → 标注 `existing`，提取增量信息
- 冲突实体：wiki 中有相同标识但信息矛盾 → 标注 `conflict`，保留两方，供审阅判断

## 不做

- 不执行代码来验证实体是否存在
- 不在无关段落中强行提取实体
- 不修改原始材料内容
