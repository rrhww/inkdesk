# routing-tree

skill-router 的路由决策树。接收用户意图后按以下顺序决定路由目标。

## 决策树

```
用户输入
  │
  ├─ 用户指定了具体 Skill 名称？
  │    → YES → 直接放行（不拦截显式调用）
  │    → NO  → 继续
  │
  ├─ 意图中包含「wiki/知识/文档/记录/摄入/查询/搜索/整理」？
  │    → YES → 进入知识管理领域分支
  │    → NO  → 进入下一层
  │
  ├─ 意图中包含「方案/代码/测试/bug/修复/部署/重构/审查/排查」？
  │    → YES → 进入研发自动化领域分支
  │    → NO  → 继续
  │
  └─ 无法判断 → 列出候选 Skill 请用户选择
```

### 知识管理领域分支

```
知识管理意图
  │
  ├─ 包含「导入/上传/加进来」→ ingest-source
  ├─ 包含「查/搜索/找到/解释/这是什么」→ answer-from-wiki
  ├─ 包含「沉淀/记下来/保存回答」→ deposit-answer
  ├─ 包含「修改页面/更新 wiki」→ patch-wiki-page
  ├─ 包含「健康/质量/检查 wiki」→ run-wiki-health
  ├─ 包含「提取/总结对话/从聊天」→ extract-insight
  └─ 多意图 → 选主导意图，末尾衔接其他
```

### 研发自动化领域分支

```
研发自动化意图
  │
  ├─ 包含「方案/设计/怎么做/架构」→ tech-solution
  ├─ 包含「审查方案/review/检查方案」→ tech-review
  ├─ 包含「写代码/实现/开发」→ coding
  ├─ 包含「测试计划/准备测试/测试范围」→ test-prep
  ├─ 包含「测试失败/修 bug/红 test」→ test-fix
  ├─ 包含「排查/报错/线上问题/崩了」→ problem-solve
  └─ 多意图 → 选主导意图，按链条顺序衔接
```

## 跨领域意图

当用户意图跨两个领域时（如「修完 bug 沉淀经验」）：
- 选主导领域（当前正在执行的动作）
- 末尾衔接链条指向另一个领域的 Skill（如 test-fix → deposit-answer）

## 冲突消解

- 多个候选 Skill 都能匹配时：列出差分，让用户选择
- 所有候选都不可行时（前置条件均不满足）：报告阻塞原因 + 推荐先解决哪个
