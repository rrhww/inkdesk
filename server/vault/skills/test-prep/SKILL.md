# test-prep

## 核心目标与边界

从需求、方案和代码变更出发，生成可执行的测试计划：

- **做**：提取测试范围 → 设计测试数据 → 定义验收点 → 输出测试计划
- **不做**：执行测试或修复失败（那是 test-fix 的职责）；编写完整测试代码（输出指导，不是可执行测试文件）

## Hard Gates

- `required_input`（change_scope）：变更范围不得为空
- `artifact_exists`（solution_doc）：方案文档必须存在作为测试范围参照

## 主流程

1. **变更分析** — 从方案和代码 diff 中提取：修改的模块、新增的接口、改动的数据路径
2. **测试范围** — 定义测试覆盖矩阵：单元测试范围 / 集成测试范围 / 端到端场景
3. **测试数据设计** — 正常数据、边界值、异常输入、并发场景数据
4. **验收点定义** — 每个关键路径的验收条件（可测量的 pass/fail 标准）
5. **测试计划输出** — 格式化为结构化的测试计划文档

## 关键决策点

- 方案中某些部分无法自动化测试时：标注为"手工验证"，给出验证步骤
- 测试数据的敏感度：不得包含生产密钥、用户真实数据；使用脱敏数据或 mock
- 测试范围过大时：按风险优先级排序，标记 P0（阻塞发布）/ P1（发布前）/ P2（发布后）

## 需要读取的资源

- `templates/`：测试计划模板（test-plan-template.md）

## 输出规格与验证

- 输出：测试计划（保存到 `runs/<run_id>/test-plan.md`）
- 验证：每个验收点可测量；测试数据可获取或可 mock；覆盖路径对应方案中的关键功能
